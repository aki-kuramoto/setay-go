# setay パス記法 (設計メモ, 進行中)

> これは設計ドキュメントです。決定済みの点と未決の論点を分けて記録します。
> 文字列/エスケープ仕様は setay.bp / unmarshal.go に、パス記法 (`:/` root・`.` 区切り・
> 数値index・DQ/SQ 引用キー) は internal/setaypath/path.bp + document.go に**実装済み**。
> 構造編集は「不変 Document + ChangeSet + Apply」モデルの phase 1 まで実装済み。残るは
> phase 2 (rename/delete/insert の操作)。

## 決定: setayq とは別物にする

setay 本体のパス記法 (Document の `Get`/`SetRaw` 等で使うアドレス表記) は、setayq
(jq 風フィルタ) のパス構文とは**意図的に別物**とする。setayq を踏まえつつ、setay に
相応しい独自の記法を定める。

### 理由

- **目的が違う**。setayq はクエリ/変換ツール。setay のパスは「単一の要素を指して
  読み書きする」アドレス表記。
- **setay の思想** (美学 §0): 世間の標準ではなく setay の意図した挙動が正。jq のパスを
  そのまま入れない。
- **jq のパスには JSON/jq 由来の癖**がある。

### 関係の注意

「なんとなく似ているが微妙に違う」は最悪の UX。別物にするなら、意図的に十分違えるか、
関係を明記すること。

## 記法の形 (決定済み)

パスは `:/` で始まり、以降は `.` 区切りのセグメント列。各セグメントは bare key /
引用キー / 数値インデックスのいずれか。

例 (実在の想定):

```
~/.app-data/u2/config/key-bender.setay:/underlay-definitions.for-daiv-internal-japanese.override-specs.0.as
```

`key-bender.setay:/` までがファイルとその中身への入り口、`:/` 以降が setay パス
(`underlay-definitions` → `for-daiv-internal-japanese` → `override-specs` → 添字 `0`
→ `as`) で、末尾は値 `"left-ctrl"` を指す。

### 先頭 `:/` (root マーカ, 単一トークン)

- パスは `:/` で始まり、setay 文書の root を表す。
- `:/` は**単一トークン**。`: /` のように間に何かが入ったものは `:/` と見做さない。
- FS ブラウザとの合成は「左のものの中身に入る」演算子として連鎖する。ファイルが zip 内
  なら `~/.app-data/bk.zip:/u2/config/key-bender.setay:/...` のように `:/` が複数現れる。
  setay パスの `:/` は特別な合流規則を持たず、この連鎖の一段にすぎない。

### ステップ区切りは `.`

- セグメントは `.` で区切る (`:/a.b.c`)。
- **末尾区切り `:/a.` や空セグメント `:/a..b` は無意味 → 不正 (reject)**。

### bare key = LenientIdentifier、それ以外は必ず引用

- 裸で書けるキーは LenientIdentifier に一致するものだけ (先頭・末尾ハイフン不可、
  中間ハイフン可)。setay.bp の `SetayBareKey` / boompaw.bp の `LenientIdentifier`。
- **LenientIdentifier に一致しない全てのキーは `"` か `'` で囲う**。
- `/` や `:` を特別視しない。「LenientIdentifier か否か」だけで引用の要否が決まる
  (結果として `/` や `:` を含むキーは引用されるが、それは一般規則の帰結にすぎない)。
- 大文字小文字は区別する。

### インデックスは数値の dot セグメント

- リストの添字は `.0`, `.1` のように数値セグメントで表す。ブラケット `[n]` は使わない。
- 負値も可 (`.-1`)。`-` は識別子の先頭になれない (先頭が `-` のものは演算子か負数
  リテラル) ので、`-1` は曖昧なく負数。

### Set の降り方 = 重複を許さない List

Set は「値を持たない Dict」ではなく「**重複を許さない List**」として降下する
(数値インデックスで降りる)。

### UtcTs は当面は終端、将来の降下の道を残す

現時点では UtcTs は終端スカラ。ただし将来、埋め込まれた TZ / 時 / 分 / 秒 のような
要素へ降りられる余地を**閉ざさない**定義にする。

### 現段階は単一値のみ (暫定)

**現段階では**単一値のみを指す (ワイルドカード/グロブ/スライス無し)。これは「複数
マッチを永久に排除する大方針」ではなく、現段階の割り切り。複数マッチは setayq の領分。

## 文字列・エスケープは Balzak に従う (Setay ⊂ Balzak)

JSON が JavaScript の派生サブセットであるように、**Setay は Balzak のサブセット**に
したい (`boompaw/project-balzak`)。よって引用キーの文字列・エスケープ記法は、setayq でも
今回の試作 path.bp でもなく、**Balzak の文字列リテラルに従う**。

### エスケープ表 (確定版・全列挙)

- **`\` + 英字/数字 = 定義済みの意味 (`n r t 0 x u U`) のみ。他はエラー (予約)**。

**安定性保証** (仕様として明記する):

> エスケープした ASCII 記号の意味 (= その記号) は将来も死守する。素の ASCII 記号は将来の
> 機能追加で special な意味を得る可能性がある (破壊的変更)。不安なら記号をエスケープして
> おけば、その意味は保証される。

補足:

- SP は除外。`\ ` は無効。SP を明示する必要が生じれば将来 `\s`/`\S` を用いる (現状未定義)。
- **DQ** では `$ { }` は素で書けない (必須エスケープ。補間 `${...}` と紛れる為)。**SQ** では
  `$ { }` は素で書ける (非補間)。`"` は DQ で必須・SQ で素可、`'` は SQ で必須・DQ で素可。
  単独の `\` は無効 (`\\` 必須)。
- `\xHH` の 0x00-0x7F は **文法レベル**で強制する (`\x` + `[0-7]` + `[0-9a-fA-F]`)。
- 数字は英字側 (厳格)。`\0` = null は定義済み、`\1` 等はエラー (予約)。「未知エスケープ=
  エラー」は実質「未知の**英字/数字**エスケープ=エラー」。

### DQ と SQ の関係 (JavaScript 型を出発点に、DQ を補間させて離れた)

Balzak は DQ のみだが, **Setay は独自に SQ (`'...'`) も許す**。**当初**は DQ/SQ を
JavaScript 型 (どちらの引用符を要エスケープにするか以外は同じ、両方とも非補間) にする
つもりだった。**今回それを覆した**: **DQ に補間 `${...}` を入れた**ので、DQ は JS の文字列
より踏み込み `$ { }` を予約する。結果として DQ と SQ は、JS の2種の引用符 (相互に同一)
より大きく違う。SQ の方が JS の文字列に近い (非補間・cooked・引用符違いだけ)。

SQ は **raw ではない**。エスケープは DQ と**全く同じものが使える**。違いは「**必須の**
エスケープが少ない」だけで、補間が無い分 `$ { }` を必須にしなくてよい。SQ で必須なのは
`'` と `\` だけで、`"` も `$ { }` も他の記号も素で書ける。これを『**最小限の必須エスケープ**』
と呼ぶ (raw でも「エスケープが少ない」でもない)。「気軽に書ける文字列」用。

### 変数展開 (補間)

Setay には変数展開 `${...}` がある (`SetayVarRef`)。これは Balzak の**補間あり文字列**
(`BzStringLit`; `${expr}`, `{` が続かない `$` は単体の `$`, 明示は `\$`) に対応する。表の
`\$ \{ \}` はこの補間文脈の為。

変数展開の文法 (`SetayVarRef` / `SetayVarFallback`) が使う記号: `${ ... ?: ... }`。
つまり `$` `{` `}` と、フォールバック演算子 `?:`。**`?` `:` は `?:` の対でのみ、かつ
`${...}` の中でのみ**現れる (単独の `?` や単独の `:` は変数展開の構文要素ではない)。

**確定**: `$ { }` は素で書けない (必須エスケープ)。`? :` は素で書ける (別形 `\? \:` も可)。
上のエスケープ表のとおり。`?:` (フォールバック) は `${...}` の中でのみ意味を持つ。

### パスの引用キー (決定)

パスの引用キーは**補間しない** (キーは「指したいキー文字列そのもの」)。引用は DQ/SQ とも
上の文字列規則に従う。`$ { }` を含むキーは **SQ で囲えば素で書ける** (SQ は非補間・最小限の
必須エスケープ)。DQ で囲う場合は補間との兼ね合いで `\$ \{ \}` が要る。

## setay 文字列実装をこの確定版に是正した (実装済み)

setay.bp / unmarshal.go を上の確定版に合わせた:

- 全印字 ASCII 記号 (SP 除く) の `\<記号>` = リテラルを許可 (`SetayAsciiSymbol`)。decoder の
  既定を「`\` の次の記号を返す」に変更。
- **DQ で `$ { }` を予約** (`SetayDqNormalChar` から `{ }` を除外、`SetayDqDollarChar` を廃止)。
  `${...}` は補間、`\$ \{ \}` はリテラル。
- **SQ は据え置き** (最小限の必須エスケープ。エスケープ自体は DQ と同じものが使える)。
  `SetaySqNormalChar` は `'` `\` のみ除外なので `$ { }` は素で書け、SQ は非補間。
- `\xHH` を 0x00-0x7F に文法強制 (`SetayHexDigit07`)。
- 未知の英字/数字エスケープはエラーのまま。
- 本体と `cmd/setay` の両パーサ再生成済み。回帰テスト `escape_test.go` 追加。

## 構造編集の API モデル (決定・phase 1 実装済み)

**不変 Document + 可変 ChangeSet + Apply で新 Document** モデルを採用:

- `Document` は完全に不変 (edits を持たない)。`String()` は常に原文。読み取り
  (`Get`/`Field`/`Node`) は pure。
- `Document.Changes()` で `ChangeSet` (可変) を得て編集を貯める。操作は Node を受け取り
  span 差し替えを記録 (`cs.SetRaw(n, text)` 等)。
- `cs.Apply() (*Document, error)` が原文に適用したテキストを**再パースして新 Document**
  を返す。原 Document は不変のまま。再パースなので新 Document の Node は fresh。適用後
  テキストが不正なら Apply がエラー (旧 `Validate` は不要に)。
- これで「保持中 Node の無効化」問題が消える (Document は書き換わらない)。overlap 検出は
  ChangeSet 内で有効 (削除領域の中を編集 → エラー)。

**phase 1 実装済み**: 不変 Document / ChangeSet / `SetRaw` / `Apply` (document.go)。
