# setay パス記法 (設計メモ, 進行中)

> これは**進行中**の設計ドキュメントです。決定済みの点と未決の論点を分けて記録します。
> 実装 (internal/setaypath/path.bp) はまだこの決定を反映していません。

## 決定: setayq とは別物にする

setay 本体のパス記法 (Document の `Get`/`SetRaw` 等で使うアドレス表記) は、setayq
(jq 風フィルタ) のパス構文とは**意図的に別物**とする。setayq の記法を踏まえつつ、
setay に相応しい独自の記法を定める。

### 理由

- **目的が違う**。setayq はクエリ/変換ツール (ストリーム, パイプ, 関数)。setay の
  パスは「単一の要素を指して読み書きする」アドレス表記。仕事が違えば表記が違ってよい。
- **setay の思想** (美学 §0): 世間の標準ではなく setay の意図した挙動が正。jq のパスを
  そのまま入れるのは「標準だから」であり、§0 が戒めた姿勢。
- **jq のパスには JSON/jq 由来の癖**がある (`.["k"]` と `."k"` の二重表記、`.[]` は
  本来クエリ概念、等)。

### 関係の注意

「なんとなく似ているが微妙に違う」は最悪の UX。別物にするなら、意図的に十分違えるか、
関係を明記すること。

## 決定済みの点

### 先頭 `:/` を必須 (root マーカ)

setay パスは `:/` で始まり、これが setay 文書の root を表す。将来、別プロジェクトの
ファイルシステムブラウザで `~/my.zip:/content.setay` のように「中身」を表す区切りとして
`:/` を用いており、これと接続して `...content.setay:/<element-path>` の形で setay 内の
一要素まで直接指定できるようにする布石。当面は setay パス単体の root マーカとして `:/`
を用いる。

### bare key の要件 = LenientIdentifier

パス中の裸のキーは setay の bare key 規則に従う: **先頭ハイフンも末尾ハイフンも不可**、
中間ハイフンは可。これらを含むキーや、その他 bare にできない文字を含むキーは `"` か
`'` で囲う。この概念は setay.bp の `SetayBareKey`、boompaw.bp の `LenientIdentifier`
として既に定義済み。

### 負値インデックスは可

`-` は識別子の先頭になれない (先頭が `-` のものは演算子か負数リテラル) ため、`[-1]` の
ような負値インデックスは曖昧なく負数として扱える (最終的な index 表記自体は未決)。

### Set の降り方 = 重複を許さない List として扱う

パスで Set に降りる場合、Set は「値を持たない Dict」ではなく「**重複を許さない List**」
として扱う。降下は list 的とし、dict のようなキー降下はしない。

### UtcTs は当面は終端、ただし将来の降下の道を残す

現時点では UtcTs は終端スカラとして扱う。ただし将来、表記に埋め込まれた
タイムゾーン / 時 / 分 / 秒 のような要素へ降りられるようにする余地があり、それを
**閉ざさない**定義にする。

## 未決の論点 (一つずつ決める)

- **ステップ区切り**。FS 的な文脈から `/` が有力だが未確定。決まれば「区切り文字を含む
  キーは引用が必要」という付随ルールも決まる。
- **キーの引用の最終形**。有力候補は setay 本体のキー表記 (bare key + setay 文字列
  DQ/SQ) の踏襲。エスケープも setay 文字列に合わせるか。
- **インデックス表記の最終形**。`[n]` か、区切りが `/` なら `:/tags/0` の数値セグメントか。
- **root だけの `:/`** (文書全体) を許すか。
- **キー / 値 / エントリの指し分け**。編集 API では「キーの改名」もあり得る。パスが値だけを
  指すのか、キーやエントリ (キー+値) も指せるようにするのか。
- **構造編集用の位置**。将来のエントリ/要素の追加・削除で、値ではなく「スロット/位置」を
  指す必要が出るか。
- **`:/` の入れ子合成**。FS ブラウザの外側パス (`~/x.zip:/a.setay:/...`) と、setay パスの
  先頭 `:/` がどう合流/入れ子になるか。
- **字句の衛生**。空白の可否、末尾区切り、空セグメント (`:/a//b`) の扱い。
- **単一値のみ** (ワイルドカード/グロブ/スライス無し) で確認。複数マッチは setayq の領分。

### 参考: キー引用の既存の判断の所在

「引用」の判断が現状どこに入っているか (setay 独自を決めるための前提):
