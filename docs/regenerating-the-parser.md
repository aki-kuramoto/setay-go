# Regenerating the parser

The setay parsers are **generated** from PEG grammars by the
[boompaw](https://github.com/) tool: the main format grammar
[`docs/setay.bp`](setay.bp), and a small path-addressing grammar
[`internal/setaypath/path.bp`](../internal/setaypath/path.bp) used by the
Document editing API. The generated Go files carry a `// Code generated by
boompaw ... DO NOT EDIT.` header — never edit them by hand; change the grammar
and regenerate.

## ⚠️ Generated parsers — keep the two `setay.bp` copies in sync

| File | Grammar | Package | Used by |
| --- | --- | --- | --- |
| `./parser.go` | `docs/setay.bp` | `package setay` | the library, and `cmd/setayq` (imports the library) |
| `./cmd/setay/parser.go` | `docs/setay.bp` | `package main` | the `setay` CLI (`setay fmt`), a standalone `package main` that does **not** import the library |
| `./internal/setaypath/parser.go` | `internal/setaypath/path.bp` | `package setaypath` | the Document path API (`Get` / `SetRaw`) |

The first two are generated from the **same** grammar (`docs/setay.bp`) into two
packages, because `cmd/setay` is a self-contained `package main` that embeds its
own copy instead of importing the library. Any change to `docs/setay.bp` must be
regenerated into **both**. Regenerating only `./parser.go` leaves `setay fmt`
parsing with the old grammar — the exact drift that once shipped the `#`-newline
empty-comment change to the library while leaving the CLI unable to parse it.

`internal/setaypath/parser.go` comes from its **own** grammar (`path.bp`) with a
single output; it is the one canonical parser for setay `Get`/`SetRaw` paths, so
there is no hand-written path parser to drift out of sync.

`cmd/setayq` imports the library package, so it needs no separate parser.

## The grammar is also mirrored in the boompaw repo

`docs/setay.bp` is the canonical grammar for this repository. The same grammar
is mirrored in the boompaw repo at `resources/grammars/setay.bp`; the two must
be kept byte-identical. Edit the grammar in one place and copy it to the other,
then regenerate.

## Commands

Run these from a checkout of the **boompaw** repo (it hosts the generator).
Point `-input` at this repo's `docs/setay.bp` and keep the input file's basename
as `setay.bp` (the generator records `filepath.Base(input)` as the
`SourceFilename` in the output header).

```bash
# From the boompaw repo. Adjust SETAY_GO to this repo's path.
SETAY_GO=../setay-go

# 1. Library parser (package setay)
go run ./cmd/boompaw/ -input "$SETAY_GO/docs/setay.bp" -output "$SETAY_GO/parser.go" -pkg setay

# 2. CLI parser (package main) — MUST be regenerated together
go run ./cmd/boompaw/ -input "$SETAY_GO/docs/setay.bp" -output "$SETAY_GO/cmd/setay/parser.go" -pkg main

# 3. Path parser (package setaypath) — only when internal/setaypath/path.bp changes
go run ./cmd/boompaw/ -input "$SETAY_GO/internal/setaypath/path.bp" -output "$SETAY_GO/internal/setaypath/parser.go" -pkg setaypath
```

The two outputs are identical except for the `package` line; you can verify
parity with:

```bash
diff <(tail -n +3 parser.go) <(tail -n +3 cmd/setay/parser.go)   # expect only the package line to differ
```

## After regenerating

- `go build ./...` and `go test ./...` must pass.
- A grammar change that adds or reshapes a node usually also needs matching
  updates in the hand-written consumers:
  - `unmarshal.go` (decoding into Go values),
  - `marshal.go` (encoding Go values),
  - `cmd/setay/formatter.go` (the `setay fmt` pretty-printer).
  These are **not** generated, so the compiler will flag most — but not all —
  mismatches. Add tests for the new syntax on every path.
