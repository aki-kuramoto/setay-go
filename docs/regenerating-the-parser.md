# Regenerating the parser

The setay parser is **generated** from the PEG grammar in
[`docs/setay.bp`](setay.bp) by the [boompaw](https://github.com/) tool. The
generated Go files carry a `// Code generated by boompaw from setay.bp. DO NOT
EDIT.` header — never edit them by hand; change the grammar and regenerate.

## ⚠️ There are TWO generated parsers — keep them in sync

| File | Package | Used by |
| --- | --- | --- |
| `./parser.go` | `package setay` | the library, and `cmd/setayq` (imports the library) |
| `./cmd/setay/parser.go` | `package main` | the `setay` CLI (`setay fmt`), which is a standalone `package main` and does **not** import the library |

Because `cmd/setay` is a self-contained `package main`, it embeds its **own
copy** of the generated parser instead of importing the library. Any grammar
change therefore has to be regenerated into **both** files. Regenerating only
`./parser.go` leaves `setay fmt` parsing with the old grammar — the exact drift
that shipped the `#`-newline empty-comment change to the library while leaving
the CLI unable to parse it.

`cmd/setayq` imports the library package, so it needs no separate parser.

## The grammar is also mirrored in the boompaw repo

`docs/setay.bp` is the canonical grammar for this repository. The same grammar
is mirrored in the boompaw repo at `resources/grammars/setay.bp`; the two must
be kept byte-identical. Edit the grammar in one place and copy it to the other,
then regenerate.

## Commands

Run these from a checkout of the **boompaw** repo (it hosts the generator).
Point `-input` at this repo's `docs/setay.bp` and keep the input file's basename
as `setay.bp` (the generator records `filepath.Base(input)` as the
`SourceFilename` in the output header).

```bash
# From the boompaw repo. Adjust SETAY_GO to this repo's path.
SETAY_GO=../setay-go

# 1. Library parser (package setay)
go run ./cmd/boompaw/ -input "$SETAY_GO/docs/setay.bp" -output "$SETAY_GO/parser.go" -pkg setay

# 2. CLI parser (package main) — MUST be regenerated together
go run ./cmd/boompaw/ -input "$SETAY_GO/docs/setay.bp" -output "$SETAY_GO/cmd/setay/parser.go" -pkg main
```

The two outputs are identical except for the `package` line; you can verify
parity with:

```bash
diff <(tail -n +3 parser.go) <(tail -n +3 cmd/setay/parser.go)   # expect only the package line to differ
```

## After regenerating

- `go build ./...` and `go test ./...` must pass.
- A grammar change that adds or reshapes a node usually also needs matching
  updates in the hand-written consumers:
  - `unmarshal.go` (decoding into Go values),
  - `marshal.go` (encoding Go values),
  - `cmd/setay/formatter.go` (the `setay fmt` pretty-printer).
  These are **not** generated, so the compiler will flag most — but not all —
  mismatches. Add tests for the new syntax on every path.
